## 1. 交付结论

本工程建立了一套内容与页面解耦的 Astro 静态个人主页。首版公开内容采用脱敏占位策略，不包含用户密码、Token、服务器地址、内部仓库、未发表结果、原始实验数据或未经确认的性能指标。

## 2. 架构说明

- `src/content.config.ts`：projects、research、notes 的 schema。
- `src/content/`：项目、研究、技术笔记 Markdown。
- `src/data/`：个人资料、教育、技能、论文、奖项和链接。
- `src/components/`：导航、卡片、标签、指标、面包屑、时间线等复用组件。
- `src/layouts/`：基础、项目、研究、笔记内容布局。
- `src/pages/`：Astro 文件路由和静态详情页生成。
- `public/`：公开文档、图片、favicon、robots 和 Open Graph 图片。

站点无数据库、后端、登录、CMS 或运行时密钥；每次构建生成静态 `dist/`。

## 3. 本地使用

首次使用：

```bash
npm install
npm run dev
```

终端会显示本地地址，通常为 `http://localhost:4321/`。修改内容后 Astro 会自动刷新。

正式检查：

```bash
npm run check
npm run build
npm run preview
```

- `check` 检查 Astro 和 TypeScript。
- `build` 生成 `dist/`，也是发布前的强制步骤。
- `preview` 在本机查看最终静态构建，而不是开发模式。

## 4. 日常内容维护

### 4.1 修改个人资料和首页

编辑 `src/data/profile.ts`：

- `name`：姓名。
- `title`：身份。
- `specialties`：Hero 关键词。
- `introduction`：首页和 SEO 简介。
- `currentFocus`：当前研究重点。
- `links`：只添加确认公开的 GitHub、ORCID、Scholar、Email 等链接。

教育、技能、论文、奖项分别维护在 `src/data/education.ts`、`skills.ts`、`publications.ts` 和 `awards.ts`。

### 4.2 添加项目

1. 复制 `src/content/projects/full-data-readout.md`。
2. 文件名使用稳定英文 slug，例如 `new-readout-system.md`。
3. 修改 frontmatter；未确认指标写 `To be confirmed`，不要填写推测值。
4. 正文保留 Overview、Motivation、Architecture、Design、Implementation、Setup、Results、Challenges、Contributions、Links 十个层次。
5. 执行 `npm run check && npm run build`。

### 4.3 添加研究主题

复制 `src/content/research/recovered-clock-phase-uncertainty.md`。研究页面必须区分 Research Question、Hypothesis、Method、Measurement Definition、Results、Interpretation 和 Limitations；不能把工程完成情况直接当作科学结论。

### 4.4 添加论文

在 `src/data/publications.ts` 中新增对象。核验题目、作者顺序、年份、venue 和 DOI；确认前保留 `placeholder: true`。PDF 只有在版权允许再发布时才能放入 `public/`。

### 4.5 添加技术笔记

在 `src/content/notes/` 新建 Markdown。分类必须是 FPGA、High-Speed Links、DAQ、Measurement 或 Statistics。代码、公式和表格由 Astro Markdown 管线处理。

## 6. Git 提交与 GitHub Pages

日常发布：

```bash
git status
git add <本次确认的文件>
git commit -m "Update portfolio content"
git push origin main
```

推送后 `.github/workflows/deploy.yml` 自动运行。仓库 Settings → Pages 的 Source 必须为 GitHub Actions。Actions 失败时先阅读失败步骤日志，本地复现 `npm run check` 和 `npm run build`，修复后再推送。

## 7. 回滚方法

如果新内容已上线但需要撤回：

1. 找到最后一个安全提交：`git log --oneline`。
2. 使用 `git revert <commit>` 创建反向提交，不重写公开历史。
3. 推送 `main`，等待 Pages 自动重新部署。

不要使用 `git reset --hard` 或强制推送处理已公开历史。

## 9. 常见故障排查

### `npm install` 失败

确认 Node.js 版本符合 `package.json` 中 Astro 的要求，删除未完成的 `node_modules` 后重新执行 `npm install`；不要手工修改 `package-lock.json`。

### Content schema 报错

根据终端指出的 Markdown 文件检查 frontmatter。分类、状态、日期、数组和 URL 必须符合 `src/content.config.ts`。

### 新页面 404

确认文件位于正确 content 目录、扩展名为 `.md` 或 `.mdx`，并重新构建。详情页 URL 使用文件名 slug。

### Pages 构建成功但页面未更新

确认最新 workflow 的 deploy job 成功、Pages Source 为 GitHub Actions，并进行无缓存刷新。不要手工上传 `dist/` 到 `main`。

### 样式在移动端溢出

检查长 URL、代码块、表格和未换行字符串；分别在 375、768、1024、1440 px 复测。
